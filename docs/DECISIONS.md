# Decisions log

Ambiguities in BUILD_SPEC resolved toward the safer option. One line of rationale each.

| # | Date | Decision | Rationale |
|---|---|---|---|
| D-001 | 2026-11-23 | Env vars are optional at boot; each module calls `requireEnv([...])` at the point of use. | Lets each phase run with only its keys, while failing loudly and by name when a key is missing. |
| D-002 | 2026-11-23 | `APP_ENV` (dev/test/prod) selects the DB: only `prod` reads `DATABASE_URL`; everything else reads `DATABASE_URL_DEV`; drizzle-kit migrates dev unless `APP_ENV=prod`. | Tests and local work can never touch prod by accident (spec §2 environments). |
| D-003 | 2026-11-23 | Embeddings stored as `vector(768)`; Gemini embedding requested with output dimensionality 768. | Spec fixes 768; current Gemini embedding models default higher but support reduced dims. |
| D-004 | 2026-11-23 | `founder_backgrounds_verified` missing → **confidence** cap (low), not a score cap. The "team background" key number (score penalty) is `founder_prior_work_evidence`. | Spec's own row says "cap confidence = low"; most pre-seed founders can't be independently verified, and capping every founder score would flatten all scores. |
| D-005 | 2026-11-23 | Added flag types `deck_arithmetic_error`, `metric_definition`, `stale_data`, and fetch failure `wrong_entity` to the spec's enums. | Spec requires these behaviours (§3.2, §7.4, §7.5) but omits them from the enum lists. |
| D-006 | 2026-11-23 | `criterion_scores.thesis_kind` (stated/revealed) column — one scorecard holds both theses' criterion rows. | Spec §6.4 requires both scores per scorecard; avoids two scorecards per run. |
| D-007 | 2026-11-23 | Seed PDFs are git-ignored; they are imported into the DB by scripts. | Case material may be confidential; the DB is the source of truth after import. |
| D-008 | 2026-11-23 | Migrations are verified in CI/local against in-memory Postgres (PGlite + pgvector) via `npm run db:verify`. | Proves the SQL is valid without touching Neon. |
| D-009 | 2026-11-23 | Added `users` table (staff allow-list + encrypted Google refresh token) and `llm_response_cache`. | Needed by §2 auth/roles and §9.1 response cache; not listed in §5. |
| D-010 | 2026-11-23 | zod v4, vitest v5, Next 15.5, Tailwind v4 (current majors at scaffold time). | Latest stable at build time; spec fixes the libraries, not versions. |
| D-011 | 2026-11-23 | `DATABASE_URL_DEV=pglite://<dir>` (or `pglite://memory`) runs the app on embedded Postgres + pgvector; tests always use in-memory PGlite with real migrations. | Work and tests proceed without network/Neon; tests exercise real SQL, never prod. Neon remains the dev/prod target. |
| D-012 | 2026-11-23 | `llm_calls.cost_usd` is numeric(18,8); INR stays 4 dp. | One embedding call costs ~$0.00002 — 4 dp rounds it to 0, breaking the "costs match Portkey within 5%" check. |
| D-013 | 2026-11-23 | The wrapper refuses to call a model with no `model_prices` row (`PriceMissingError`). | An unpriced model would spend without counting toward the daily kill switch. |
| D-014 | 2026-11-23 | Migration `0000_init` was regenerated (not amended with 0001) for D-012. | It had never been applied to any database. From now on, schema changes get new migrations. |
| D-015 | 2026-11-23 | Rule text R1–R14 comes from the spec; the citation (meeting #, chunk id, verbatim quote) is attached only when the rule's anchor words are found in one imported note chunk. Otherwise source = "unverified" and the UI shows it red. | No fabricated citations. |
| D-016 | 2026-11-23 | MeetRecord is seeded as a portfolio company even if not found in the imported notes (marked unverified). | R5: a false-alarm conflict flag beats a missed conflict. |
| D-017 | 2026-11-23 | Knowledge import and embedding are separate passes (`kb:import -- --no-embed`); embedding fills only NULL vectors and is re-run safely; changed text clears its old vector. | Import works before model keys exist; re-runs cost nothing. |
| D-018 | 2026-11-23 | Repair retry and each call are separate `llm_calls` rows (`<step>` and `<step>:repair`), both costed. | Cost totals must match Portkey's request log. |
| D-019 | 2026-11-23 | Provider SDK imports (`portkey-ai`, `@google/genai`, `langfuse`) are banned outside `src/ai/` by an ESLint rule. | Enforces "one wrapper" mechanically. |
| D-020 | 2026-11-23 | Langfuse missing keys: no-op tracer with a warning in dev/test; hard error in prod. Langfuse receives PII-masked input/output. | Phased build without hiding gaps in prod; "send less, log less". |
| D-021 | 2026-11-23 | Numeric checks: formula claims (TAM/SAM/SOM) flag only at ≥2×; cross-checks (seats×price vs MRR etc.) flag at >10% as `metric_inconsistency`, ≥2× as arithmetic error. Per-call USD at 8 dp. | Spec's ≥2× rule for formulas; Talkbook's 340×₹500 vs ₹2.1 L (1.24×) must still surface. |
| D-022 | 2026-11-23 | `/apply` form fields are provisional (company, sector, stage, location, incorporated, raise, valuation, one-liner, source/referrer, founders, deck). | Real form PDFs not provided yet; align when they arrive. |
| D-023 | 2026-11-23 | Consistency checker flags any differing TEXT claim (credentials, credit/capital source) as `unjudged`; the LLM judge may later downgrade to low but never delete. | Kill criteria 3 & 11 — false alarm preferred to a miss. |
| D-024 | 2026-11-23 | Status transitions are a whitelist; approved/rejected/on_hold/outreach_sent/closed are human-only (system may close only after a founder's "not interested"). `needs_attention` always needs a reason. | R12 / kill criterion 4 enforced in code, not just UI. |
| D-025 | 2026-11-23 | Rate limit: Postgres fixed window (5/min per keyed-hash of IP) when Upstash isn't configured. | Spec allows it; IPs stored only as hashes. |
| D-026 | 2026-11-23 | Uploaded decks go to Vercel Blob with `access: "private"` (local `.uploads/` in dev without a token; required in prod). | Decks are confidential; no public URLs. |
| D-027 | 2026-11-23 | ~~**Known issue:**~~ **Resolved by D-033.** Vercel serverless bodies are capped (~4.5 MB); 20 MB decks via `POST /api/applications` will fail when deployed. Fix in Phase 11: client-side direct upload to Blob (`@vercel/blob/client`) then submit references. | Works locally; must change before go-live. |
| D-028 | 2026-11-23 | Until staff auth (Phase 8), middleware blocks every internal page/API in `APP_ENV=prod` (503); only `/apply`, `/privacy`, `POST /api/applications`, `GET /api/health`, `/api/inngest` are public. | Applicant data must never be served unauthenticated. |
| D-029 | 2026-11-23 | Seed import creates applications from `<Company>_Deck.pdf` + `_Form.pdf` with sector/stage/founders empty; the extraction step fills them from the form PDF. | Form PDFs need model extraction (keys); nothing is guessed from filenames. |
| D-030 | 2026-11-23 | Without Inngest, the no-op queue leaves applications in `received`; when Inngest is wired, a sweep enqueues all `received` rows. | Nothing lost while the queue isn't configured. |
| D-031 | 2026-11-23 | Scheduling: "≥2 business days out" counts Mon–Fri from the IST date; "≤14 days" from now; follow-up/escalation at ≥48h exactly; public holidays not modelled. | Spec boundaries (D11); holidays covered by the human approving each email. |
| D-032 | 2026-11-23 | `/api/health` is unhealthy in prod unless the database probe succeeds. | A deploy health check must not pass with no database. |
| D-033 | 2026-11-23 | Uploads bypass the function body limit: browser → `POST /api/uploads` (rate-limited, 12/min/IP) gets a client token scoped to `incoming/{deck,form}/*.pdf`, PDF only, ≤20/10 MB, random suffix, 10-min validity, 1-day TTL → uploads straight to **private** Blob → submits JSON with pathnames (~0.5 KB). Server only accepts `incoming/` refs whose kind matches, re-fetches with a size cap before buffering, re-checks PDF magic bytes, copies into the application's storage via the unchanged intake path, then deletes the temp upload (on success, rejection or honeypot; TTL is the backstop). Multipart stays for local dev without a Blob token. | Fixes D-027 without trusting the client: every limit is enforced twice (token + server). |
